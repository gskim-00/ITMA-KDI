### 2-1. 엑셀에서 '수정 일시'·'수정자' 제외
- 현재: 기본 형식 26개에 '수정 일시'·'수정자'(자동 입력, 업로드 시 무시)가 포함. 업로드하면 업로드 시각·업로드한 사람으로 자동 기록
- 변경
  - 기본 형식을 **24개**로: 기본 정보 15(번호~제조년월) / 장비 정보 6 / 장비 상세 3 → 업로드 템플릿·'기본 항목' 다운로드 공통
  - '사용자 지정 항목' 다운로드에서도 두 컬럼 제외(목록에 표시 중이어도 엑셀에 넣지 않음)
  - 다운로드 안내창의 항목 목록·문구(26개 → 24개), 템플릿 `작성 안내` 시트 갱신
  - 업로드: 이전 파일에 두 컬럼이 있어도 지금처럼 조용히 무시('현재 없는 컬럼' 안내에도 표시하지 않음). 저장 값은 그대로 업로드 시각·업로드한 사람

### 2-2. 비밀번호 입력란 안내를 보안 정책에 맞게 표시
- 현재: 보안 설정의 비밀번호 정책(최소 길이·대문자·소문자·숫자·특수문자, `security_settings`)은 서버 검사에만 쓰이고, 화면 안내는 고정 문구 — 신규 계정 등록 "최소 6자 이상 입력하세요"(정책 기본값 8자와도 다름), 주의사항 "최소 6자 이상", 일괄등록 팁 "최소 6자 이상". 나머지 화면은 안내 없음
- 변경: 현재 정책으로 안내 문구를 만들어 아래 화면의 새 비밀번호 입력란 아래에 표시 (예: "8자 이상, 영문 대문자·소문자·숫자·특수문자(!@#$%^&*) 포함")
  | 화면 | 위치 |
  |------|------|
  | 관리자 › 신규 계정 등록 | 비밀번호 입력란 아래, 주의사항, 일괄등록 팁 |
  | 관리자 › 사용자 현황 › 사용자 정보 수정 | 새 비밀번호 입력란 아래 |
  | 관리자 › 내 정보 변경 | 새 비밀번호 입력란 아래 |
  | 상단 메뉴 › 프로필(비밀번호 변경) | 새 비밀번호 입력란 아래 |
  | 비밀번호 강제 변경 / 초기 비밀번호 설정 화면 | 새 비밀번호 입력란 아래 |
- 방식: 정책 문구 생성 함수 1개(서버) + 템플릿 공통 주입(`app.py` context processor) → 정책을 바꾸면 모든 화면에 바로 반영. 보안 설정 저장 후 관리자 화면 안의 안내도 새로고침 없이 갱신
- 파일: `app.py`, `blueprints/auth.py`·`blueprints/admin.py`(정책 문구 함수 — 두 파일의 중복 검사 함수 옆), `templates/admin/sections/add_user.html`, `templates/admin.html`, `templates/admin/sections/admin_profile.html`, `templates/base.html`, `templates/force_change_password.html`, `templates/password_setup.html`, `static/js/security-settings.js`
- 참고: 비밀번호 초기화 기본값 `123456`(`admin.py` `DEFAULT_RESET_PASSWORD`)은 정책 기본값(8자·조합)에 맞지 않음 — 이번 범위 아님, 9번 확인 사항

### 2-3. 사용자 현황 › 사용자 정보 수정에서 권한 변경
- 현재: 수정 창은 이름·이메일·새 비밀번호·허용 IP만 변경(`/admin/update_user`). 권한(role: 사용자 user / 매니저 manager / 관리자 admin)은 신규 등록 때만 지정
- 변경
  - 수정 창에 '권한' 선택(사용자/매니저/관리자) 추가, 현재 권한 표시
  - 서버 검사: admin만 변경 가능, **본인 권한은 낮출 수 없음**, **마지막 관리자(admin)는 다른 권한으로 바꿀 수 없음**
  - 권한이 바뀐 사용자는 다음 로그인부터 적용(현재 세션 권한은 로그인 시 저장됨) — 즉시 적용이 필요하면 9번 확인 사항
  - 감사 로그에 "권한 변경: 이전 → 이후" 기록, 사용자 현황 목록 권한 표시 갱신
- 파일: `blueprints/admin.py`(`update_user`, 사용자 목록 조회에 role 포함 여부 확인), `templates/admin.html`(수정 창), `static/js/user-manager.js`

### 2-4. 자산번호 `ITMA-0000` 방식
- 현재: 자산 등록(추가 화면·엑셀 업로드) 때 내부 자산 코드 `asset_code`가 `ITMA-0001`처럼 자동으로 붙음(`_make_generated_asset_code`). 자산 목록의 '자산번호' 컬럼은 사용자가 입력하는 `asset_id`이고, 수정 화면 제목 옆 배지·변경 이력의 '자산번호'는 `asset_code`(ITMA-0001)를 표시 → 같은 '자산번호'라는 이름으로 두 값이 보임
- 변경: **원하는 방향 확인 필요 (9번 확인 사항 1)** — 확인 후 계획 보완

### 2-5. IP·MAC 입력 형식
- 현재: 자유 입력, 형식 검사 없음
- 변경
  - IP/Subnet: `X.X.X.X/X` 형식만 허용 — 각 자리 0~255, `/` 뒤 0~32. 입력 중 숫자·`.`·`/` 외 문자 차단, 저장 시 형식이 틀리면 칸에 오류 표시
  - Mac address: 16진수(0-9, A-F)만 입력, **2자리마다 하이픈(-) 자동 입력**, 최대 12자리(`AA-BB-CC-DD-EE-FF`), 대문자로 정리. 12자리가 아니면 저장 시 오류
  - 빈칸은 지금처럼 허용
  - 적용 화면: 자산 추가/수정 화면, 상세정보 모달(장비 탭)
  - 서버 저장 API(`/assets/save`, `/assets/<id>/details`)도 같은 규칙으로 검사(화면 우회 방지)
  - 엑셀 업로드·이미 저장된 값 처리는 9번 확인 사항 4
- 파일: `static/js/itma-asset-form.js`, `static/js/itma-handler.js`, `blueprints/ITMA.py`, `templates/ITMA/asset_form.html`(placeholder·안내)

   - (나) 자동 코드 형식 변경 (예: 앞글자·자릿수·카테고리별 접두어) — 원하는 형식 알려주기
   - (다) 자산번호를 비워 두면 자동 코드(`ITMA-0001`)를 자산번호로 채워 넣기

   - IP의 `/X`(서브넷) 필수 여부 (계획 기본값: 필수)
   - 이미 다른 형식으로 저장된 값: 그대로 두고 그 자산을 수정할 때 고치게 함 / 형식을 자동 정리(예: MAC `00:11:22…` → `00-11-22…`) (계획 기본값: MAC은 12자리면 자동 정리, IP는 그대로 두고 수정 시 검사)
   - 엑셀 업로드: 같은 규칙 적용 여부 (계획 기본값: MAC은 자동 정리, 형식이 틀린 IP·MAC은 비우고 결과 메시지에 건수 안내)
5. **비밀번호 초기화 기본값 `123456`** — 정책(8자·조합)과 맞지 않음. 이번에 함께 바꿀지 (계획 기본값: 이번 범위 아님)
